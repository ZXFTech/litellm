# 项目设计规范

适用于本项目的组件、样式和布局开发、检查与调整。这些是项目可编辑的普通文档。你可以增加、修改或删除要求，随后同步索引和适用范围。当前文件是依据，上游版本、旧报告或聊天记忆不替代本次读取。

## 阅读顺序

1. 先读本索引及 [项目要求](project/index.md)，确认任务范围和明确的替代条款。
2. 涉及颜色、字体、密度或可访问性时，读取相应基础文档。
3. 根据 [组件索引](components/index.md) 或 [布局索引](layout/index.md) 读取适用规则，再查看项目当前源码、样式和调用处。
4. 检查任务返回问题与证据；调整任务只在授权对象中修改实现并复查。不能通过降低规范掩盖实现问题。

设计后台管理页面时，从 [后台管理设计规范](admin/index.md) 依次阅读全局布局、页面区域与模板、通用组件与交互。

## 写入范围与命令副作用

先明确本次获准修改的项目文件。验证命令也受相同范围约束，不能因为叫“检查”或带 --noEmit 就视为不写文件。执行前读取实际脚本和配置，确认会写入哪些文件；TypeScript 开启 incremental 时，tsc --noEmit 仍可能写入 tsconfig.tsbuildinfo 等缓存。只授权修改指定实现时，不运行会改写其他项目文件的命令。只有确认当前配置支持且不会产生额外文件，才可在命令行临时关闭增量写入，不为验证改项目配置。不能确认副作用或命令被任务禁止时，使用只读源码复查，并将未运行的验证标为 NOT RUN；隔离副本验证按任务授权执行。

修改前和结束时，用只读方式列举项目文件并比较字节或摘要，可在内存中核对，不为审计在项目内新增文件。范围覆盖项目的隐藏、未跟踪、被 Git 忽略及生成文件；可排除 .git 内部和明确不参与本次操作的外部依赖目录，但不能仅因文件被忽略就排除缓存。记录检查方法、范围及排除目录。非 Git 项目同样核对磁盘文件；仅看 git diff、git status、工具退出码或只读回目标文件，都不能证明没有额外写入。

报告实际新增、修改、删除的文件，并区分本次变化与任务开始前已有内容。只有完整的前后核对支持时，才能声明“仅授权文件变化”。若缺少起点、范围不完整或有无法归因的变化，明确标记变更范围为 BLOCKED。发现额外写入时报告 FAIL 和真实路径，保留现场，不擅自删除或回滚来隐藏副作用；验证命令成功也不能把任务写入范围判为通过。

## 检查记录

报告本次目标、实际读取的规范路径与条款、源码位置、检查方法、发现和证据，逐项使用 PASS、FAIL、NOT RUN、BLOCKED。分别说明源码判断、模型审阅和真实浏览器验证。文件存在、脚本成功、来源相同不代表设计符合，也不代表 AI 已自动读取入口。

本地文件有修改、规范和组件版本不同或没有来源基线，都不妨碍按当前规范检查。任务中相关文件再次变化时重新读取并更新结论。来源和升级差异另外记录。
