# 后台管理设计规范

适用于以管理业务记录、处理任务和配置系统为目标的后台应用。先确定布局层，再根据任务选择页面模板，最后按所用控件和交互模式落实细节。同一应用内的页面共享导航、密度和状态语义。

| 层级 | 职责 | 适用文档 |
| --- | --- | --- |
| 基础 | 定义设计 Token、尺寸节奏、焦点与操作语义 | [语义颜色与主题](../foundations/colors.md)、[字体与圆角](../foundations/typography.md)、[间距与密度](../foundations/spacing.md)、[焦点、键盘与状态](../foundations/accessibility.md) |
| 全局布局 | 定义顶栏、侧栏、主区、内容容器及其响应式关系 | [全局布局](global-layout.md) |
| 页面区域与模板 | 分配业务区域与操作，选择 T01 至 T06 的任务结构 | [页面区域与模板](page-templates.md) |
| 组件与交互 | 定义 C01 至 C12 的内容、操作、状态及响应式行为 | [通用组件与交互](components.md) |

## 规则等级

| 等级 | 含义 |
| --- | --- |
| MUST | 必须遵守，适用于本条明确涵盖的业务范围。 |
| SHOULD | 推荐作为默认做法。偏离时说明任务需求及保留的用户能力。 |
| MAY | 可按业务、权限、内容量和组件能力选择。 |
| EXCEPTION | 仅在条款写明的条件和作用范围内采用，并记录原因及影响。 |

先满足基础与上层的通用要求，再采用模板或组件层的具体条款。项目规则有明确替代范围时在该范围内生效。颜色、字形、间距、圆角和控件变体继续由共享主题定义。角色权限、业务数据、可用组件与实现接口由实际项目决定。
