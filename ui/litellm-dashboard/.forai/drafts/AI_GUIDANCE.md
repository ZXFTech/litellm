# 当前项目规范接入

本文件随 ai-guidance 条目交付到 .forai/drafts/，供项目审阅接入方式。仅规范模式同时交付 design-guidelines 和本草案，可用于检查项目已有实现。Agent 或 Skill 的启用由项目另行决定。

## 应用入口

1. 确认 design/forai/index.md 及其相对链接可读。检查适用的根和嵌套项目指引，保留项目既有要求。
2. 根据同目录 AGENTS-entry.md 准备精确补丁，入口只引用后代 design/forai/index.md，局部规则保留在下级普通文档。
3. 按项目要求完成模型审阅。对既有 AGENTS.md 展示包含上下文的精确 diff，由操作者明确应用；没有文件时同样先审阅新建内容。Registry 不直接创建或覆盖实际 AGENTS.md、CLAUDE.md、SKILL.md。
4. 在新会话用普通组件检查任务验证自动发现，记录实际读取工具、路径、条款和源码。没有宿主读取记录时保留 NOT RUN，不能因文件存在或模型自述标为已接入。

## 每次任务

重新读取当前索引和适用规范，再通过 components.json、tsconfig、目录、源码、类型及调用处确定实际 API。没有组件时不虚构导入。检查任务不写项目文件，也不在原项目运行会生成文件的安装或构建；需要运行时在隔离副本中执行，或标为 NOT RUN。

后台管理任务从 `design/forai/admin/index.md` 阅读全局布局、页面模板及组件交互。用同目录的 `page-references.md` 查看业务页面结构和状态，用 `workspace-source.md` 阅读 Markdown 源码快照。按本项目的组件接口、路由、权限与数据适配。

调整任务只改授权的实现并复查，不通过降低规则掩盖问题。规范任务可以直接增删改普通 Markdown，并同步索引。条款含糊、冲突或链接缺失时列出原文和影响，未确认部分标 BLOCKED，其余明确范围可继续检查。

补装组件、修改 API 或编辑规范后，下次任务直接读取当前文件，入口不需要重新激活，不生成规范副本、installed-catalog 或 effective-rules。规范与源码版本不同、来源未知、本地有修改都不是设计失败。

## 验证与变更范围

所有命令都受任务写入范围约束，类型检查不自动等于只读。执行前读取脚本及配置，确认包括 tsconfig.tsbuildinfo 在内的缓存与生成物；tsc --noEmit 在 incremental 开启时仍可能写文件。只授权目标文件时，不能执行有额外项目写入的验证。仅在当前配置支持且已确认无额外写入时临时关闭增量，不修改项目配置；否则采用只读复查，并将未执行项记为 NOT RUN。

按规范索引中的写入范围流程，修改前后只读核对完整项目文件，包含隐藏、未跟踪、忽略和生成文件，记录方法与排除目录，不在项目内写审计文件。git diff/status 或只读回目标文件不足以证明“只改目标”，没有 Git 时仍核对磁盘字节。报告真实新增、修改、删除，区分既有内容；核对不完整标 BLOCKED，额外写入标 FAIL 并保留现场，不擅自删除、回滚或隐瞒。

## 报告与入口状态

每项记录目标、实际读取的规则路径和条款、实现位置、检查方法、发现、证据及 PASS / FAIL / NOT RUN / BLOCKED。分别记录静态结果、AI 设计判断、浏览器或设备结果。来源和更新差异另外说明。

missing 表示当前所需路径缺失，draft 表示只有候选入口，conflicted 表示当前指引链或要求有未解决冲突。ready 需要当前宿主成功加载的实际记录，不与源码摘要或规则版本绑定。普通规则修改不使入口自动失效。

## 新会话探针

先显式指定规范做只读检查，再以只描述组件检查的普通任务验证入口。随后保持入口不变，修改本地规则，新会话应读取新要求、发现旧实现偏差并在授权后调整。再修改本地 API，新任务应根据源码正确调用。工具读取日志和实际差异是证据，旧报告或仅口头声明不是证据。

公开发布、Vite、其他 AI 宿主与本地 Codex 分别验收。当前资料不承诺这些环境已通过。
