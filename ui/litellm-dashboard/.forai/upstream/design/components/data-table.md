# Data Table：数据表格规范

适用于数据表格及其组件示例。保留参考示例的内容与交互，新增状态延续已接入的组件和主题约定。

## 内容与交互基线

* 按当前基础组件库和风格查阅 reference UI。先列出正常、RTL 等实际示例及其数据、列、格式和交互，再与应用逐项对应；附加状态不替代或缩减原示例。
* 核对原始记录与顺序、状态文字、邮箱显示、金额格式和对齐、筛选、排序方向、列显隐、单行选择与全选/半选、选中计数、行菜单及分页。参考存在语言切换时，同时核对文案、方向和浮层。
* 表格行使用稳定记录 ID。排序、筛选、分页或刷新不能把选择、编辑草稿和保存结果关联到另一条记录；隐藏数据列后，占位行和编辑行的 colspan 随可见列数更新。

## 三项状态处理原则

1. **尽可能保留已有内容。** 后台刷新和保存失败保留已加载记录、筛选、排序、分页、列设置、选择与未保存输入。请求失败不把仍可用的整个列表或页面变为空白。
2. **错误尽可能局部化。** 单行或单元格错误在对应位置提示；列表请求错误留在当前列表内。权限被拒绝时不得为保留内容继续展示受限记录、编辑内容或之前操作产生的敏感反馈。
3. **每个异常状态提供明确下一步。** 说明失败原因，并提供适用的重试、清空筛选、切换账号、重新登录、取消编辑或返回列表等操作；只有“出错了”或短暂 Toast 不足以承载需要恢复的错误。

## 必须区分的八类状态

| 状态 | 展示与保留 | 下一步 |
| --- | --- | --- |
| 首次加载中 | 尚无数据，保留表头和列表区域，在正文展示进度或骨架；不显示“空列表”或“无结果”。 | 等待完成；按所在场景提供取消或重置，阻止无效操作和重复请求。 |
| 正常数据展示 | 完整展示记录、工具栏、行操作、选择计数与分页，保留原有格式及行为。 | 支持原有查询与操作。 |
| 已有数据，后台刷新中 | 保留已有记录及查询、选择状态，使用局部刷新提示；刷新失败显示原因并继续显示上次成功的数据。 | 失败可重试刷新；已有内容仍可查看。 |
| 真正的空列表 | 数据源本身没有记录，保留列表结构，明确说明暂无数据，计数与分页反映实际情况。 | 提供适用的创建、导入或载入示例数据入口。 |
| 搜索或筛选无结果 | 数据源有记录但当前条件没有匹配项，保留查询条件，文案与真正空列表区分。 | 可调整条件或清空筛选，恢复原有记录。 |
| 首次加载失败 | 请求失败且尚无可用记录，保留表头和列表主体，在正文说明网络问题、请求超时或服务异常等已知原因，不伪装成空列表。 | 提供重试加载。 |
| 权限不足 | 区分无权限与登录过期，说明原因；保留允许显示的结构，隐藏受限数据和派生反馈。 | 无权限可切换账号或返回列表；登录过期可重新登录。示例中的恢复操作须注明本地模拟。 |
| 单行编辑保存失败 | 保留该行原有已保存值和未保存输入，仅在该行提示原因；其他记录继续展示。筛选、翻页或切换行后，失败草稿与结果仍按记录 ID 保留。 | 可重试保存或明确取消编辑；保存成功后只更新对应记录，取消才丢弃对应草稿。 |

* 示例页为八类状态提供可定位、可操作的演示，正文与本页目录同步。新增示例复用既有记录和独立交互卡片，避免为每个状态另建一套表格。
* 数据请求错误与渲染错误边界分开处理。错误边界只接管发生渲染异常的表格子树，提供重试恢复，其他示例不受影响；网络失败或行保存失败不触发整页错误边界。
* 明确本地模拟请求与真实请求的边界。重置或卸载演示时取消未完成任务，阻止旧回调回写；重试期间保留相关上下文并阻止重复提交。

## 样式与无障碍

* 复用现有 Table、Input、Button、Checkbox、菜单和交互卡片，沿用当前风格的尺寸、字体、圆角、边框、间距、图标及语义 token。新增进度、空态、错误和行编辑不另造颜色或控件配方。
* 与 reference 对照浮层宽度、对齐、层级、语言和方向；保留正常与 RTL 示例的差异，不把普通表格的尺寸机械套到 RTL 浮层。
* 控件、提示和表格内容在卡片内完整展示，窄屏可换行或重排；不以新增横向滚动、裁切文字、隐藏操作或省略字段规避布局问题。检查焦点环及扩展点击区域仍落在卡片可用空间内。
* 进度使用可访问状态提示，加载或刷新区域标记 aria-busy。错误有持续可读的说明，输入错误通过 aria-invalid 和说明关联到对应控件；错误信息不只依赖颜色。
* 行选择、排序、菜单和恢复操作可用键盘完成；纯图标按钮有明确名称。禁用、半选、展开和焦点语义与实际状态一致。

## 验证清单

* 对照参考源码与当前风格配方，在真实界面逐项操作原有示例，验证数据、格式、筛选与排序、显隐、选择与半选、行菜单、复制、计数、分页及参考提供的 RTL/语言切换；不能只用正常态截图证明交互齐全。
* 对八类状态验证触发、保留内容、错误范围和下一步，特别检查刷新失败保留旧记录、筛选无结果可清空、权限切换不残留数据，以及行保存失败的草稿、重试与取消。
* 核对快速重复操作、重试、重置和卸载后的异步结果；确认旧任务不会修改新状态，独立卡片互不影响。
* 在已登记主题、明暗模式、三档密度、常规宽度与窄屏检查新增状态及浮层。结合截图、可见内容边界与 scrollWidth/clientWidth 检查卡片和实际内容区，同时核对伪元素、焦点环及扩展点击区域的边界。
* 记录逐项结论、必要的项目适配差异和实际验证证据；未运行项目如实标记。规范记录本身不代表运行或视觉验证通过。
