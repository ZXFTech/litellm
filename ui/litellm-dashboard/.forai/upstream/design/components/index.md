# Components：组件通用规范

本文件维护跨组件复用的实现与展示规则，具体控件的配方、尺寸和演示行为放在对应下级目录。

## 职责与接口

* 新组件先明确用户任务、组件负责的行为及调用方负责的业务决策。优先组合已有组件和内置选项；已有行为仅需新外观时增加共享变体；出现现有组合无法承载的稳定职责时再新增基础组件。业务请求、权限策略和业务数据适配放在业务组合层。
* 沿用现有分区；新结构只将需要独立替换、重排或复用的区域拆成子组件，保留必要的语义与行为约束。先满足已知场景，实际出现稳定共性后再提取复用接口。
* 尺寸、视觉变体、交互状态和内容插槽分别表达；同一维度使用明确选项，避免互相矛盾的布尔组合。尺寸切换保持操作语义，状态变化沿用原有尺寸体系。
* 有状态组件沿用所选基础库的受控与非受控约定，明确状态由谁持有、默认值如何初始化及变更事件的含义；调用方传入的状态与组件内部状态保持单一来源。

## 实现与组合

* 核对基础组件、`cn()` 和 `cva` 是否已接入；缺失时补齐必要基础，不导入不存在的模块。多外观和多尺寸集中定义，不复制类名合并工具。
* 界面中用于选择预设选项的下拉选择器统一复用项目共享的 ForAI `Select`，由组件负责触发器、展开列表与主题状态。迁移已有下拉选择器时保留字段标签、说明、必填、禁用、选中值和键盘行为。
* 消费组件时，`className` 主要负责宽度、位置、外边距等布局。颜色、字体、控件高度和内部间距由主题、风格和共享变体管理。
* 尺寸与内边距从当前风格配方取得。同一行的控件保持相容的高度、字号与图标尺寸，不从其他组件的数值推断当前组件。
* 布局优先使用 `flex` / `grid` 配合 `gap-*`；等宽高使用 `size-*`；单行截断使用 `truncate`。
* 控件后方的按钮、徽标、计数和状态文字应与控件本体垂直居中对齐。位于控件上方的字段标签和下方的错误提示不参与控件行的对齐；控件与关联元素使用同一行的 `flex` / `grid` 布局，窄屏允许换行，控件高度变化时仍按控件本体居中。
* 组合组件沿用已接入实现的分区、子组件结构和统一内容边距。保留 `data-slot`、`data-size` 和分组标记，避免破坏内部对齐规则。
* 图标统一使用项目选定的图标库，大小和内部留白由宿主组件的配方控制。
* 统一处理 hover、focus-visible、disabled、展开和 invalid 状态。焦点使用 `ring`，控件错误边框和错误焦点提示使用 `destructive`；不要只移除焦点提示而不提供替代。
* 已启用的点击、选择、展开和导航控件，实际可点区域统一使用 `cursor: pointer`，包括能激活控件的关联标签。光标样式由组件自身提供。禁用或不可访问的区域不显示可点击光标。直接编辑文本、拖动和调整尺寸的区域使用各自的操作光标。
* 对于输入区与内嵌图标按钮组成的组合控件，错误和键盘焦点提示统一显示在控件外框，内部图标按钮不重复叠加错误或焦点描边。内部按钮获得键盘焦点时，外框仍须显示可见焦点提示；保留 `aria-invalid`、可访问名称及键盘操作等无障碍语义与行为。
* 沿用浮层组件的层级与动画约定，避免业务页面随意叠加极大的 `z-index`。

## 状态与无障碍底线

* 按组件实际能力列出适用状态及转换。涉及数据获取时区分加载、空内容、无匹配结果、失败和权限不足；异常提供适用的恢复路径，保留仍有权限展示的内容与用户上下文。具体状态流程按下级控件规范执行。
* 使用符合任务的语义元素，保留基础库的键盘行为；交互控件有可访问名称，字段标签、说明和错误与对应控件关联。状态同时提供文字或可访问语义，不能只依赖颜色或图标。
* 浮层打开、关闭及操作导致内容移除时，沿用基础库的焦点管理，并在触发元素已不存在时提供合理的焦点落点。异步状态变化按需要提供可访问播报，避免重复播报。

## 组合场景验证

* 新组件除独立陈列外，至少在一个代表性实际组合中验证；按风险选择窄栏、浮层、工具栏、长内容或多实例场景，检查容器约束、焦点顺序、视觉层级和实例间状态隔离。复用已有演示即可，记录实际验证的场景与遗漏项。

## 公共示例与主题扩展的目录组织

* 公共组件页位于 `src/app/[theme]/component/<name>/page.tsx`，供所有主题复用。公共交互演示保留在相邻的 `_components/`，基础控件继续从 `@/components/ui/*` 等现有共享实现导入，不按主题复制组件。
* 主题特有示例位于 `src/components/<theme>/examples/<name>/page.tsx`，同模块导出示例区块组件和目录 `headings`；有状态的交互及浏览器 hook 放在相邻的 `_components/`。这里的 `page.tsx` 是被导入的普通组件，不是 Next.js 路由。
* 路由入口负责 Metadata、主题校验、页面标题和组装。公共页先渲染公共示例，仅对匹配的主题追加专属示例；同时向 `DocsPage` 合并专属 headings。不要只追加正文而遗漏目录，也不要把业务示例默认放到所有非 base 主题中。
* 主题独有整页同样复用文档外框，向外框传入 `headings` 与 `children`。朝夕现有业务页使用 `ComponentExamplePage` 保留标题、组件引用与页脚，业务 section 仍从示例模块导入。
* 区块优先复用 `DocsSection`；目录与 section 的 `id` / `title` 保持一致，锚点在同一页面内唯一，条件显示的内容与目录同步。示例组装保持服务端组件，仅状态、事件和浏览器能力进入客户端组件。

## 组件示例页展示

* 每个 section 直接按“标题、介绍、示例陈列区”组织，标题和介绍不额外包装。一般陈列不使用 article、逐项卡片、装饰背景或多余嵌套。
* 一般陈列中的示例共享同一父容器，默认水平左对齐、垂直居中，允许换行。间距复用全局刻度，当前陈列间距统一使用 `gap-4`。
* 交互演示中的控件及其计数、状态等关联信息必须放在同一卡片内，默认水平排列、垂直居中，窄屏允许换行。独立的操作与反馈使用不同卡片区分。
* 交互卡片使用低对比度背景，复用现有语义色（例如 `bg-muted/40`）及主题边框；圆角、内边距和间距沿用当前风格。简单演示卡片仅保留必要的分组容器，一般陈列不因控件可操作就自动改为交互卡片。
* 有状态的交互卡片包含标题行：标题左对齐，状态重置按钮右对齐，两者保持同一行。重置仅影响本卡片的关联状态；异步演示需同时取消未完成任务，避免重置后旧回调重新写入状态。
* 结果文字、计数等信息持续保留，可随新交互更新，由本卡片的重置按钮主动清除。
* 链接类组件的示例不得跳转到其他页面、外部站点或新标签页。保留链接外观及键盘、焦点语义，点击只使用当前页锚点或更新当前交互卡片的反馈。此规则适用于组件陈列与演示；示例页自身的站点导航和本页目录不受此限制。

## 从参考库落地

* 落地前盘点任务范围内 reference UI 的实际示例、展示内容与交互，逐项对应到应用；同时核对变体、语言/RTL、禁用与异常状态，不能以单张正常态截图代表完整迁移。
* 完成后回到参考源码和当前风格配方复核内容、交互及样式；新增状态复用现有组件、语义 token 和布局约定。记录必要的项目适配差异和未覆盖项，不把静态检查或规范落盘当作实际界面验证。

* 参考库 `registry/bases/` 中的 `cn-*` 类是风格标记，构建脚本会用所选风格的配方将其展开为 Tailwind 类；不要只复制标记而遗漏对应样式。
* 采用同一基础组件库和风格的完整实现，核对主题、动画、辅助类及依赖是否齐全。保留必要的状态属性和无障碍结构。
* 参考目录保持为资料来源。除非任务明确要求，不修改参考源码，不为普通组件任务安装、运行或迁移整个参考仓库。
* 代码格式遵循当前应用配置。参考库的格式配置可供理解类名排序，不自动替换应用的 ESLint 或格式化配置。
